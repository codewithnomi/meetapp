# F01 Accounts & workspaces: Tasks (STEPS)

Small steps, done in order, on branch `feat/F01-accounts`. Each step is committed and pushed when its tests pass (D026). Tick `[x]` when done and verified.
Before a step uses Better Auth or a Microsoft detail, the matching item in design.md "Verify at build" is checked against the current docs; a difference updates the design first and the owner is told.

## Backend: sign-in

- [x] **T1: Libraries, settings and the code map.**
  - Vet the D049 libraries with `/add-dependency` (versions, licences, activity recorded in D049): better-auth, bullmq, sharp, react-router, @tanstack/react-query, react-hook-form, oauth2-mock-server (dev only) and the common-passwords list. Each is **installed in the task that first uses it**, because `pnpm check` fails on unused libraries.
  - New settings in `config.ts` and `.env.example`: `BETTER_AUTH_SECRET`, `DATA_ENCRYPTION_KEY`, `GOOGLE_*`, `MICROSOFT_*`, `SUPPORT_EMAIL`, `APP_PUBLIC_URL`.
  - The new folders go into `docs/engineering/project-structure.md` and the structure check.
  - Covers: AC-F01-33 (start-up checks part).
  - Check: `pnpm check` green, including the licence check; a missing or short `BETTER_AUTH_SECRET` stops the backend, naming it.

- [x] **T2: Database tables.**
  - Better Auth tables, generated by its CLI into a Drizzle migration, with our added user fields.
  - Our tables: `workspaces`, `workspace_members`, `invitations`, `join_requests`, `member_removals`, with the unique rules: one owner per workspace, one personal workspace per user, one pending invitation or request.
  - Done with `/db-migration`.
  - Covers: AC-F01-22, 14 (database part).
  - Tests: TC-F01-59.
  - Check: migrations run on an empty and on the F00 database; a second owner and a second personal workspace are refused by the database.

  - Log redaction paths.
  - Covers: AC-F01-03, 05, 06, 11, 27, 33.
  - Tests: TC-F01-06, 10, 11, 13, 16, 29, 70, 80.

- [x] **T4: Rate limits.**
