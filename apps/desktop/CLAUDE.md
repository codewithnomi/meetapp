# Rules for apps/desktop
- The Electron shell around apps/web. Security settings (S17, AC-F00-24) live in `src/main/security.ts` and `guards.ts`; never loosen them (no nodeIntegration, sandbox and contextIsolation always on, pages can't open windows (only main opens the two F16 call-window kinds, D079), CSP without inline scripts). The one approved exception is `'wasm-unsafe-eval'` for the background tool's WebAssembly (owner, 2026-10-27, D073); JavaScript eval stays blocked. The e2e tests in tests/e2e/desktop check them.
- The preload exposes only `window.meetapp.platform`, `window.meetapp.auth` (F01: sign-in calls main makes; the token stays in main), `window.meetapp.media` and `window.meetapp.deviceKey` (F02: camera/mic/screen access, the share picker, the device key), `window.meetapp.files.save` (F03: save a chat file from our backend with "Save as"), `window.meetapp.power` (F14: computer locked), `window.meetapp.app.onTrayCommand` (F04: the tray menu asks the screens to open Settings or set a status; checked by `isTrayCommand`) and `window.meetapp.callWindows` (F16: report calls, carry out the small windows' button presses, send the mini window's live-video pictures). The F16 small windows get their own preload with only `window.meetappCallWindow` (`onState`, `act`, `onFrame`) and their own session that refuses every permission (D079). Anything new there needs a design change first.
- Camera, microphone and screen rules live in `media-permissions.ts`; `lockDownSession` (guards.ts) is the only place permission handlers are set, because Electron keeps only the last one.
- Pure logic goes in files without `electron` imports so it can be unit-tested; Electron wiring stays thin (main.ts, guards.ts, app-protocol.ts).
- Built with plain Vite (D039): `scripts/build.ts`. The main process must not `await` app readiness at the top level (Electron becomes ready only after main.ts finishes).
- VS Code terminals set ELECTRON_RUN_AS_NODE; anything that starts Electron removes it.
